# HTTP Error Code Reference

**Webアプリケーションにおけるエラーページ実装の参照資料** - HTTPステータスコード4xxおよび5xxの定義・原因・対処法


---

## 概要

HTTPステータスコードは、クライアントのリクエストに対するサーバーの応答状態を示す3桁の数値である。RFC 9110で標準化されており、先頭の数字によって5つのクラスに分類される。本文書では、エラーページ実装時に頻出する4xx（クライアントエラー）と5xx（サーバーエラー）を解説する。

---

## 4xx Client Error

クライアント側に起因するエラーを示すステータスコード群である。リクエストの構文誤り、認証・認可の失敗、存在しないリソースへのアクセス等が該当する。

### 400 Bad Request

クライアントエラーと認識される要因により、サーバーがリクエストを処理できない、または処理しないことを示す。

- **主な原因**：リクエスト構文の誤り、不正なリクエストメッセージフレーミング、欺瞞的なリクエストルーティング
- **対処法**：リクエストの形式・パラメータを確認する。ブラウザのキャッシュとCookieを削除し再試行する

### 401 Unauthorized

リクエストされたリソースに対する有効な認証資格情報が不足していることを示す。HTTP仕様上は「unauthorized」と記載されるが、意味的には「unauthenticated（未認証）」である。

- **主な原因**：認証情報の未送信、認証トークンの期限切れ、認証情報の誤り
- **対処法**：正しい認証情報でログインし直す。サーバーは`WWW-Authenticate`ヘッダーで認証方式を提示する必要がある

### 403 Forbidden

クライアントの身元は判明しているが、リソースへのアクセス権限がないことを示す。401とは異なり、認証済みであっても認可されていない状態である。

- **主な原因**：アクセス権限の不足、管理者によるアクセス制限、IPアドレスベースの制限
- **対処法**：リソースの所有者または管理者にアクセス権限を確認する。権限のあるアカウントで再認証する

### 404 Not Found

サーバーがリクエストされたリソースを発見できないことを示す。URLの誤り、リソースの削除、存在しないエンドポイントへのアクセス等で発生する。セキュリティ上の理由から、403の代わりにリソースの存在を隠蔽する目的で使用される場合もある。

- **主な原因**：URLの入力誤り、リソースの移動または削除、リンク切れ
- **対処法**：URLの正確性を確認する。検索機能やサイトマップからリソースを探す

### 408 Request Timeout

アイドル状態の接続において、サーバーが未使用の接続を切断する意図を示す。クライアントからのリクエストがなくても送信される場合がある。

- **主な原因**：ネットワーク接続の不安定、サーバーの待機時間超過、クライアント側の処理遅延
- **対処法**：ネットワーク接続状況を確認する。リクエストを再送信する

### 429 Too Many Requests

クライアントが一定時間内に過剰なリクエストを送信したことを示す（レートリミット）。

- **主な原因**：API呼び出し頻度の超過、自動化スクリプトによる大量リクエスト
- **対処法**：`Retry-After`ヘッダーで指定された時間まで待機する。リクエスト頻度を調整する

## 5xx Server Error

サーバー側に起因するエラーを示すステータスコード群である。サーバーがリクエストの処理に失敗した、または処理能力がない状態を示す。

### 500 Internal Server Error

サーバーが予期しない状況に遭遇し、リクエストを処理できないことを示す汎用エラーである。より適切な5xxコードが存在しない場合に使用される。

- **主な原因**：サーバーサイドコードのバグ、設定エラー、未処理の例外
- **対処法（管理者向け）**：サーバーログを確認し、エラーの根本原因を特定する。アプリケーションコードと設定を検証する

### 501 Not Implemented

サーバーがリクエストメソッドをサポートしておらず、処理できないことを示す。GETとHEADはサーバーが必ずサポートしなければならないメソッドであり、これらに対して501を返すことは許容されない。

- **主な原因**：サーバーが対応していないHTTPメソッドの使用、未実装の機能へのアクセス
- **対処法（管理者向け）**：サーバーまたはホスティングプロバイダーに必要な機能の実装状況を確認する

### 502 Bad Gateway

ゲートウェイまたはプロキシとして動作するサーバーが、上流サーバーから無効な応答を受信したことを示す。

- **主な原因**：上流サーバーの障害、プロキシ設定の誤り、上流サーバーからの不正な応答
- **対処法**：上流サーバーの稼働状況を確認する。プロキシ設定を検証する。時間をおいて再試行する

### 503 Service Unavailable

サーバーがリクエストを処理する準備ができていないことを示す。メンテナンス中または過負荷状態で発生する一時的な状態である。

- **主な原因**：サーバーメンテナンス、アクセス集中による過負荷、リソース枯渇
- **対処法**：`Retry-After`ヘッダーが提示されている場合は、指定時間後に再試行する。管理者は負荷分散やスケーリングを検討する

### 504 Gateway Timeout

ゲートウェイまたはプロキシとして動作するサーバーが、リクエストを完了するために必要な上流サーバーからの応答を、制限時間内に受信できなかったことを示す。

- **主な原因**：上流サーバーの応答遅延、ネットワーク遅延、タイムアウト設定の不足
- **対処法**：上流サーバーの応答時間を確認する。タイムアウト設定を調整する。時間をおいて再試行する
